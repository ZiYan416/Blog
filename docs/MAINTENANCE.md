# 开源项目维护手册

本手册记录本仓库的**项目特定**维护约定；通用行为准则、Issue/PR 默认模板和安全报告指引可由账号级公开 `.github` 仓库统一提供。仓库已有的 Issue/PR 模板优先级高于账号默认模板，不应为统一而覆盖。

## 分支及合并

- `master`：发布/稳定分支；`develop`：日常集成分支。
- 常规功能及缺陷修复从最新 `develop` 派生短期分支，PR 默认指向 `develop`。
- 稳定版本由维护者审查后通过 PR 从 `develop` 合并到 `master`。紧急修复先评估影响，修复后同步回 `develop`。
- 禁止未经审查直接合并依赖升级、数据库迁移或涉及鉴权的变更。不要自动批量合并 PR。
- 临时分支在 PR 合并、确认不再需要后再删除；长期分支、既有工作分支不作批量清理。

## Issue 与 PR

1. 先搜索现有 Issue/PR，避免重复。Bug 说明复现步骤、预期/实际结果、环境和脱敏证据。
2. 大型功能建议先讨论范围、兼容性及验收标准；安全漏洞不要在公开 Issue 中披露细节。
3. PR 说明变更目的、影响范围、相关 Issue、测试结果、风险及回滚方式；有界面改动时提供合适的截图或动图。
4. 至少完成作者自检、适用的自动化检查和维护者审查后再合并。CI 通过是必要信号，不等于自动批准变更。

## 本仓库验证矩阵

GitHub Actions 的 `.github/workflows/ci.yml` 当前针对 PR 和推送到 `master` / `develop` 执行：

| 检查 | 命令或机制 |
| --- | --- |
| 代码规范 | `npm run lint` |
| 类型检查 | `npm run typecheck` |
| 单元测试 | `npm test` |
| 生产构建 | `npm run build` |
| 浏览器回归 | `npm run test:e2e`（Playwright） |
| 数据库验证 | `supabase start`、`supabase test db` |

开发者至少完成与变更相关的检查；涉及数据库、路由、部署或安全的修改应执行对应专项验证。记录未运行的步骤，不将未经运行的测试写为“已通过”。

## 依赖与安全

- 依赖升级一次聚焦少量直接关联的软件包；重大版本升级单独评估兼容性、构建、数据库迁移及回滚。
- `package-lock.json` 与 `package.json` 保持一致；不要提交密钥、真实用户数据或本地环境文件。
- 发现安全漏洞时优先使用仓库的私密漏洞报告入口（如已启用）；不可用时先通过维护者公开的私密联系渠道沟通，勿在公开 Issue 中贴出利用细节。
- 启用 Dependabot、安全告警、自动合并及分支 Rulesets 属于仓库 Settings 管理任务；不因存在本手册就视为已开启。

## 发布和回滚

1. 确认目标提交、CI、待解决的阻断问题及必要的数据备份/迁移说明。
2. 更新版本说明和 README 中用户需要了解的变更，并由维护者确认发布。
3. 生产部署出现回归时优先撤销对应部署或回滚到最近的已验证版本；数据库迁移须单独核查可逆性。
4. 保留版本、测试证据与事故复盘链接，避免仅通过删除分支处理故障。
